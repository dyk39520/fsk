# test-case-writing Skill

## 适用场景

- 单份需求、用户故事、验收标准或页面流程已经比较清楚。
- 需要快速产出可执行的常规功能测试用例。
- 覆盖正向、异常、边界场景，输出给评审或执行。

## 推荐输入

- 被测对象和模块名称
- 需求或验收标准
- 页面入口、字段、按钮和业务规则
- 测试环境、权限和测试数据约束
- 已知风险或历史缺陷

## 执行要求

1. 先理解业务流程、核心成功路径和主要失败风险。
2. 按业务风险和影响排优先级，不平均铺用例。
3. 正常、异常、边界场景都要覆盖，避免重复用例。
4. 信息不足时先给可执行初版，并列出假设和信息缺口。
5. 不编造未提供的接口、字段、错误码或业务规则。

## 输出要求

每条用例至少包含：

- 用例编号
- 用例名称
- 模块
- 测试类型
- 设计方法
- 优先级
- 前置条件
- 测试数据
- 测试步骤
- 预期结果
- 需求追踪
- 执行状态
- 备注

## 项目定制规则

该项目要求 AI 同时输出 CSV 和 XLSX，两套文件使用完全相同的表头。

固定表头：

```text
用例编号,用例名称,模块,测试类型,设计方法,优先级,前置条件,测试数据,测试步骤,预期结果,需求追踪,执行状态,备注
```

测试设计方法只能从以下选项中标注：

```text
等价类划分、边界值分析、判定表、状态迁移、错误猜测、场景法
```
