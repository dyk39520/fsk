# 注册/登录测试用例生成 Prompt 示例

你是一名资深 QA 测试设计专家。请基于下面的项目信息，为 fskinandlaser 美容服务平台的注册、登录功能生成一组可执行测试用例。

## 输入信息

项目名称：fskinandlaser 美容服务平台

被测模块：

1. 用户注册
2. 用户登录
3. 登录会话和状态

已知业务流程：

- 用户可以通过邮箱注册账号。
- 注册时需要填写邮箱、手机号、密码等信息。
- 登录支持邮箱登录和手机号登录。
- 登录失败后页面会给出错误提示。

## 测试设计方法要求

必须使用以下方法，并在“设计方法”列标注：

```text
等价类划分
边界值分析
判定表
状态迁移
错误猜测
场景法
```

## 覆盖要求

至少覆盖以下场景，但不要只写这些场景：

注册模块：

- 合法邮箱、合法手机号、合法密码注册成功
- 邮箱格式错误
- 手机号格式错误
- 密码为空
- 密码长度边界
- 重复邮箱注册
- 重复手机号注册
- 必填项为空

登录模块：

- 正确邮箱和密码登录成功
- 正确手机号和密码登录成功
- 密码错误
- 邮箱格式错误
- 手机号格式错误
- 密码为空
- 账号为空
- 登录后会话保持
- 退出登录后不能继续访问需要登录的页面

## 输出格式

必须同时输出 CSV 和 XLSX 两个文件，文件名按被测对象命名，例如：

```text
注册登录测试用例_最终.csv
注册登录测试用例_最终.xlsx
```

CSV 第一行表头固定为：

```text
用例编号,用例名称,模块,测试类型,设计方法,优先级,前置条件,测试数据,测试步骤,预期结果,需求追踪,执行状态,备注
```

XLSX 必须使用与 CSV 完全相同的表头。

## 用例字段要求

- 用例编号：使用稳定短编号，例如 `REG-001`、`LOGIN-001`。
- 优先级：按业务影响和失败概率分为 P0、P1、P2、P3。
- 测试步骤：每步可执行，不写模糊动作。
- 预期结果：必须可以判断通过或失败，不能写“系统正常”。
- 需求追踪：写真实需求或风险编号；没有时使用稳定短标签，例如 `REG-REQ-001`。

## 质量要求

- 不为了凑数量写重复或低价值用例。
- 假设和缺失信息单独列出。
- 高风险场景必须包含正向、异常和边界用例。
- 输出完成后请附上评审建议和自动化候选说明。
